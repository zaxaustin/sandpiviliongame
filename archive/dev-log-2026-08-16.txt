THE WASM QUESTION, ANSWERED NO — and why it is written down
----------------------------------------------------------------

The steward preferred WASM to avoid a native module and ~34 MB. Tested
first, as asked. It fails twice over:

  device:'wasm'  ->  "Unsupported device. Should be one of: dml, cpu."
  remove onnxruntime-node  ->  ERR_MODULE_NOT_FOUND, hard, no fallback

transformers.js registers only native providers under Node and imports
onnxruntime-node statically. The only route to WASM is convincing it that
main is a browser — which also flips kokoro-js's voice loader from
readFile() to fetch()+caches.open(), neither of which exists in a main
process. So it would break offline voices to save disk.

AND DirectML IS BROKEN ON THIS MODEL, which was a bonus finding:

  Non-zero status code returned while running ConvTranspose node
  ... DmlExecutionProvider ... The parameter is incorrect.

So the GPU path is not merely unnecessary on an A770 — it does not run.
Its 17.7 MB DLL is excluded with confidence rather than with a shrug.

⚠ THE SHARP STUB IS LOAD-BEARING AND FAILS ONLY WHEN PACKAGED.
transformers.js requires sharp AT IMPORT TIME. Deleting it outright is
ERR_MODULE_NOT_FOUND and takes the voice with it — measured, then the

than returning something plausible, so a future image feature breaks
loudly here instead of quietly somewhere far away.


----------------------------------------------------------------
THE INTERFACE DID NOT CHANGE, AND THAT WAS THE HARD PART
----------------------------------------------------------------

All fifteen exports of tts.js keep their signatures. overlays.js has
about sixty call sites and none of them knows there are two engines.

The difficulty was never audio. `speak()` returns a boolean SYNCHRONOUSLY
and `isSpeaking()` is polled eighteen times to draw button labels. Neural
synthesis is async and the first sentence takes 2.5 s. If `isSpeaking()`
only became true when sound started, every read-aloud button in the
Pavilion would sit unchanged for two and a half seconds after being
pressed and people would press it again. So `play.on` is set BEFORE ANY
AWAIT, and everything asynchronous happens behind it.

The other half: the wait is drawn as a wait. Machine latency is a cost
and never dressed as pace (rule 9), so there is a "warming the voice"
state rather than a fake progress bar.

WHAT GOT BETTER RATHER THAN WORSE: position. The system engine estimates
a character offset from CHARS_PER_SEC = 14 because Web Speech cannot
seek. Every Kokoro chunk arrives with the exact text it was made from, so
progress and a +-10 s skip are exact. VOICE-PLAN.md predicted this in
July and called it "a genuine improvement, not a workaround." It was.

THREE ROUTING RULES worth keeping:
  · stopSpeaking() silences BOTH engines, always, never an else. A stop
    that only reaches the selected backend leaves the other talking with
    nothing able to stop it.
  · speak() stops the other engine first, or switching the setting
    between two presses leaves two voices reading different pages.
  · speakFrom() takes webSpeech(), NOT ttsAvailable() — ttsAvailable()
    widened the moment a second engine existed, and that function
    dereferences window.speechSynthesis on its next line. A crash that
    would only ever appear on somebody else's machine.


----------------------------------------------------------------
⚠ stream() HANGS IF THE SPLITTER IS NOT CLOSED
----------------------------------------------------------------

Handed a plain string, kokoro-js's stream() emitted THREE of four
sentences and then stopped forever on an unsettled await. Found on a
probe, before a line of integration existed. TextSplitterStream +
close(), always. The live suite reads a four-sentence text and carries
its own timeout, so if the close() ever goes the run is red rather than
eternal.

That is a read-aloud that stops mid-paragraph with no error — the house
failure mode, and it would have been blamed on the model.

----------------------------------------------------------------
A 977 MB INSTALLER, AND THE GATE SAID GREEN
----------------------------------------------------------------

Trying to make the packaging Mac-safe produced the worst regression this
project has had, and the gate certified it.

THE SEQUENCE, because each step was individually reasonable:

  1. The size prunes (`!.../darwin/**`, `!.../linux/**`, DirectML) were in
     the TOP-LEVEL `files` glob. On Windows that is a saving. On a Mac it
     deletes the binaries the Mac needs — and MAC-BUILD.md hands this repo
     to somebody with a Mac and twenty minutes. They would have built a
     dmg whose voice was broken, with no actionable error: the model
     downloads fine, only the runtime is missing.

  2. So they moved into `build.win.files` / `build.mac.files`.

  3. ⚠ electron-builder implies a match-everything pattern for a `files`
     array containing ONLY negations. So the platform list did not narrow
     the common allow-list — it replaced its effect with "everything,
     minus four folders". `dist/**` + `electron/**` stopped being a
     boundary.

  4. And `release/` is auto-excluded ONLY when it is the output directory.
     CLAUDE.md tells you to build with
     `--config.directories.output=$TEMP/sp-build` to dodge an editor's
     EPERM lock — which makes `release/` an ordinary project folder
     holding a 225 MB unpacked app.

  116 MB -> 977 MB, with 87 entries of the PREVIOUS build packed inside
  the new app.asar. Two documented workarounds, one 861 MB regression.

⚠ AND verify:release WENT GREEN ON IT. Every check in that script asks
whether the docs AGREE with the artifact. Nothing asked whether the
artifact was sane. The hash matched itself perfectly, so the gate printed
a tick over a download nobody could use. A 260 MB ceiling lives there now
— a tripwire for this shape of regression, not a budget.

THE FIX IS CODE, NOT GLOBS. build/after-pack.cjs prunes by
`context.electronPlatformName` after packing, where the platform is a
variable rather than a pattern. It cannot widen an allow-list because it
does not touch one, and it REFUSES to delete the binaries for the
platform it is building for — the Mac bug, expressed as a property of the
code. Verified: `after-pack: onnxruntime pruned to win32/x64 — 208 MB ->
16 MB`, installer back to 116 MB, zero release/ entries in the asar.

A small one worth keeping: the first draft of that file would not parse.
`ReferenceError: darwin is not defined` — because a doubled star followed
by a slash inside a block comment CLOSES the comment, and the comment
quoted the offending glob literally. Globs are spelled out in words in
that file now.

6 sabotage cases on the packaging guards, all caught.
