dev log — 2026-07-08
(the day the Library learned to hold real books, and left the browser to go get them)

Full detail lives here so README.md can stay a current-state reference
instead of a growing changelog. Everything below actually happened and
was verified — hash-checked, tested in a headless browser, or confirmed
against a real API — not just planned. See git history for the actual
diffs.

================================================================
SESSION 1 — a real reading journal, and the Dhammapada goes live
================================================================

- Reading notes: a 📝 Your notes panel in the Reader, `data.bookNotes[slug]`,
  personal to the save, never touching Supabase or the shared shelves.
  Visible from both the summary and full-text views. Caught and fixed a
  real contrast bug live (note cards inheriting the Reader's parchment-page
  dark-ink color, making text unreadable against the card's own dark
  background).
- Reader laid out as two columns on wide screens — book on the left,
  notes on the right — so a thought doesn't require scrolling away from
  the page to reach the note box.
- The Dhammapada's full text (F. Max Müller, 1881, Gutenberg #2017) — built
  in a prior session but never pushed to production — finally landed in
  Supabase for real: 66,849 characters, hash-verified byte-for-byte before
  and after. A second Caravan run (a new `tools/caravan/suttacentral.py`
  connector) sourced the same treatment for Satipatthana, the Metta Sutta,
  and Anapanasati straight from SuttaCentral's real bilara API — a genuine
  gotcha found and documented: `keys_order`'s sequence doesn't always match
  `translation_text`'s own dict order, so document order has to come from
  walking `keys_order`, never the dict directly.

================================================================
SESSION 2 — the scaling conversation, and standing up local storage
================================================================

- A real strategy conversation about what happens once the Library holds
  thousands of books instead of a handful — landed on: keep Supabase for
  metadata/search (it already does this well into the millions of rows),
  add local object storage (MinIO, via Docker) for the actual book text,
  explicitly reject a second "NoSQL" database as solving a problem that
  doesn't exist here. Written up in `LIBRARY-SCALING-PLAN.md`.
- Docker installed, MinIO stood up (`sand-pavilion-minio`, auto-restarting,
  data on this machine's own disk, bucket `sand-pavilion-library`,
  anonymous-read only). A real bug caught before it cost anything: Git
  Bash's MSYS2 runtime silently mangles Docker `-v` bind-mount paths — the
  first container passed its health check while writing to nowhere at
  all. Fixed (`MSYS2_ARG_CONV_EXCL="*"`), verified by confirming MinIO's
  own files actually appeared on the host disk afterward.
- Migrated all four Theravada full texts out of Supabase's JSONB column
  and into MinIO objects, hash-verified. The Reader's `openFullText` now
  tries the inline (zero-setup) copy first, falls back to a MinIO fetch,
  and fails visibly with a real message if MinIO isn't running — verified
  both states, including the failure path with MinIO deliberately stopped.
- `tools/caravan/push-fulltext.py` — attaches a full text to an existing
  shelf entry in one command (`mc pipe` over Docker, no bind mounts,
  sidesteps the MSYS2 gotcha entirely). Proved live: James Legge's real
  1891 Tao Te Ching translation (Gutenberg #216, matching the translator
  already cited for that shelf entry) attached to the existing Daoism
  entry. Caught a second real bug in the process: `mc` runs inside its
  own container, so "localhost" from in there means the container itself,
  not the host — fixed by rewriting to `host.docker.internal` for that
  one hop only.
- Per-page read-aloud added to the full-text reader (previously read-aloud
  only covered the curated summary) — stops cleanly on page turn instead
  of overlapping into the next page.

================================================================
SESSION 3 — Classics and Science shelves, and a real research pipeline
================================================================

- Renamed the long-unused "Nature" shelf slot (built, wired, never
  populated) to **Classics** — zero new layout work, just gave an already-
  physical shelf a real purpose. **Science** already existed the same way.
- Four new full texts added and hash-verified: Meditations (Marcus
  Aurelius), The Republic (Plato, tr. Jowett), The Nicomachean Ethics
  (Aristotle), and On the Origin of Species (Darwin, 1859 first edition) —
  all sourced from Project Gutenberg, IDs confirmed against the real API
  before fetching, never guessed from memory.
- Built `tools/caravan/semanticscholar.py` and `tools/caravan/arxiv.py`.
  Semantic Scholar's unauthenticated pool turned out to be persistently
  rate-limited from this machine (confirmed after repeated backoff, not a
  blip); their API-key form flatly refuses personal email addresses
  (gmail.com explicitly named in their own error) — a hard rule, not a
  bug to route around. arXiv needs no signup at all and became the real
  path forward. Two more real bugs caught: arXiv's certificate chain
  doesn't verify against this Python install's default trust store
  (fixed with `certifi`, confirmed Gutenberg's chain verifies fine so it
  wasn't systemic) and non-ASCII author names were silently mangling in
  this Windows console's default encoding (fixed by forcing UTF-8 on
  stdout).
- Five real papers on AI memory downloaded and verified against arXiv's
  own API before fetching: Attention Is All You Need (1706.03762), Neural
  Turing Machines (1410.5401), Memorizing Transformers (2203.08913),
  Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
  (2005.11401), and MemGPT (2310.08560).
- A chapter/paper summarizer added to the Research Desk: paste in text you
  have legitimate access to, your local AI condenses it into study notes,
  saved as a private project note — never sent to the shared Library. The
  real boundary that makes this legitimate: personal summaries of your own
  material, not redistribution of anyone else's copyrighted text.

SESSION 4 — testing what's actually buildable in-game, and building it
================================================================

- Tested, not assumed: which Caravan sources a browser can reach directly,
  no backend. Gutenberg's raw-text host, arXiv, and Semantic Scholar are
  all CORS-blocked for real content (some of their search/metadata
  endpoints are open, the actual book/paper text isn't). SuttaCentral's
  full API — search, suttaplex, and the bilara text endpoint — is fully
  open.
- Built a live "🔍 Browse SuttaCentral" panel directly into the in-game
  Caravan Desk: search, preview, and fetch a real sutta's full text
  straight from the browser, landing in the Steward Review Queue exactly
  like every other intake path. Ported `suttacentral.py`'s bilara-to-
  clean-text parser into JS to make this work. Tested live end to end —
  a real search, a real fetch, real clean text, correct CC0 license.
- A bean bag chair (Library, a reading nook) and a bench (just outside
  the Library's door) — new tile types, added to `SOLID`, drawn to match
  the game's existing visual language, verified with real screenshots.
- Clarified the project's own "in vs. out" philosophy in the README:
  do it in the Pavilion where the game genuinely can; step outside,
  by hand or by script, where it genuinely can't; bring the result back
  in. The Request Board and `tools/caravan/` already were this — the
  Request Board's own text said so the whole time.
- A ledger-style status overview built as a shareable artifact — the
  first time this project's own state was presented as a polished,
  standalone page rather than a chat wall of text.

SESSION 5 — README overhaul, and the Sand Pavilion opinions
================================================================

- Decided, deliberately: Supabase and Vercel stay standing (real,
  non-reproducible data lives there — 8 of 28 live library texts only
  exist in Supabase, not the zero-setup fallback) but go quiet for now.
  Local-first — Docker, MinIO, local Ollama — is where daily use
  actually happens; the cloud pieces are dormant groundwork for a later
  multi-user phase, not torn down.
- README rewritten for a professional, current-state read rather than a
  running changelog — the detailed narrative of everything built across
  2026-07-08 moved here, to this file, where it belongs.

SESSION 6 — Library cleanup, and a real desktop app goes live
================================================================

- Seven shelf entries that stood in for a real book but only had a
  summary — Heart Sutra, Diamond Sutra, Bodhicaryavatara, Kalama Sutta,
  Sigalovada Sutta, Zhuangzi, Religions of Ancient China — removed from
  both `seed.js` and the live Supabase table. Found, separately, eight
  more placeholder-only entries live in Supabase that had drifted ahead
  of `seed.js` entirely (added via the drafting pipeline, never
  reflected locally); five given real full text (Chemical History of a
  Candle, Our National Parks, Man and Nature, Tesla's
  Inventions/Researches/Writings, the Vibhaṅga Sutta), three removed
  for lack of an open-license source. Caught a real bug along the way:
  two books tagged `tradition:'Nature'` had no matching shelf and were
  unreachable in-game; reassigned to Science.
- Electron picked over Tauri (pure JS, same language as the whole
  codebase). `electron/main.cjs` proxies Ollama requests through Node's
  own `fetch` instead of the renderer's — the permanent fix for the
  browser CORS wall that requires `OLLAMA_ORIGINS` configured exactly
  right. Proven live, not assumed: a real `GET /api/tags` and
  `POST /api/chat` round-trip through the bridge, then an actual
  in-game conversation. A first-run "install Ollama" link (routed to
  the real system browser via `shell.openExternal`, not a second app
  window) when no local AI is reachable. A real Windows installer
  (`npm run electron:build`) and a one-click dev launcher batch file.
- A real environment gotcha: the sandboxed shell used to build this had
  `ELECTRON_RUN_AS_NODE=1` set, making Electron's own binary run as
  plain Node instead of opening a window — not a code bug, worked
  around per-launch. A second, separate gotcha hit building the
  installer: Vite's own dev server, left running in the background,
  fought with electron-builder's file extraction (its HMR watcher
  picked up the newly-written installer files mid-build), producing a
  Windows `EPERM` on a folder rename three times in a row before the
  actual cause was found.
- The Research Desk broadened to help with real-world projects, not
  just research topics — new quick-starts ("break this into next
  steps," "what do I need to get started," "what could go wrong") and
  a system-prompt rewrite recognizing "build a garden" as a different
  kind of ask than "study a topic."
- The Mountain Monk moved from the Library to the Pavilion Keep — a
  quieter room, off the Grounds' main paths, for an actual one-on-one
  conversation instead of competing with the shelves. Formalized the
  role split in both his and the Steward's AI personas: the Monk for
  conduct/meaning/practice, the Steward for daily life.
- The Writing Desk gained real AI help: "Ask the Steward," grounded in
  today's intention, rhythm blocks, and what's due soon.

SESSION 7 — Real search, a Library-storage health check, more books
================================================================

- Real search: a Postgres `tsvector` column + GIN index on
  `library_documents` (title weighted highest, tradition/summary next,
  section text lowest), plus a `search_library_documents()` RPC
  returning results ranked by `ts_rank`. The Index panel's search now
  calls it (debounced, race-safe against a faster follow-up keystroke),
  falling back to the existing local substring match if Supabase isn't
  configured or a query errors. Verified live: a word-stemmed query
  ("mindfulness breathing") correctly found the right book with no
  literal substring match.
- A passive Library-storage status line, same pattern as the existing
  Ollama one — checks MinIO's real `/minio/health/live` endpoint, but
  only shown when the mirrored Library actually has a MinIO-backed
  book, so it never alarms a visitor who isn't using local storage.
  Wired into `Store.libraryReady`, a hook that had existed unused since
  Phase 3.
- Five more real texts: the Buddha's first and second sermons and the
  Mangala Sutta (SuttaCentral, Bhikkhu Sujato), Epictetus's Enchiridion
  and Plato's Apology/Crito/Phaedo (Gutenberg). Caught two
  mis-attributions before shelving anything — the actual file headers
  named Thomas W. Higginson and Henry Cary as translators, not the
  translators a web search's summary text had suggested — checked the
  real source before writing anything into the database.
- `library-inbox/` — one subfolder per source website for manually
  downloaded books, gitignored like `library-sources/` — and
  `LIBRARY-GROWTH-PLAN.md`: the license-first rule (free to read is not
  the same as free to shelve), why hand-picked connectors stay the
  approach over a general scraper, and a real categorized source list.
- Actually installed and ran the packaged installer for the first
  time (previously only the build itself had been proven, never the
  real install-and-launch). Surfaced a real, previously-unverified gap:
  the installed app (`file://` origin) and the dev/browser version
  (`http://localhost:5173`) have completely separate, mutually
  invisible `localStorage` — basic same-origin browser behavior, not a
  bug — meaning save progress doesn't carry over between them. The
  existing Export/Import save feature (built a prior session) turned
  out to already be the exact bridge needed, no new code required.

SESSION 8 — Closing the loop, the sect look, and the Monk's standing priority
================================================================

- The actual gap named directly by the user as the project's real
  point: "I want my day to be at ease where this place can help me
  find direction and the tools needed to make use of the knowledge
  provided." Closed the concrete version of it: every book note in the
  Reader now has a "Bring to today's plan" button — one click, and it
  lands as a "spark" on the Writing Desk's planner-day record,
  attributed to the book it came from, folded straight into the
  Steward's day-planning system prompt alongside due items and past
  embers. Verified live end to end.
- The player/NPC sprite redesigned from a plain colored rectangle with
  a stroked hood outline into an actual robed silhouette: shoulders
  wide, waist gathered at a sash, hem flaring back out; wide sleeves
  draping down from the shoulder; dark hair with a topknot and a
  sect-colored pin. One shared helper keeps the look consistent across
  walking and all three meditation poses. Verified visually, not just
  read back as code — real screenshots captured from a running
  Electron window via `webContents.capturePage()`, cropped and
  upscaled with PowerShell's `System.Drawing`, reviewed, and iterated
  once (the first sleeve version read as flat triangular wings, fixed
  by angling them down). Player robe recolored purple-and-black per
  direct request; sash changed from cream to black across every
  character. `CHARACTER-CUSTOMIZATION-PLAN.md` written for the real
  color/hairstyle picker, deliberately deferred rather than built now.
- A standing rule, the user's own words: "the mountain monk should
  always be the best local model, never let that change for other
  things... this is a Buddhist temple first and foremost." Built
  `bestLocalModel()` (reads whatever `isAvailable()` already confirmed
  is installed, picks the largest by parameter count) and
  `chatOptsFor()`, applying it — plus `think:true` and a new `deep`
  token/timeout tier well past what everything else gets — to the
  Monk's live chat and anything drafted from a conversation with him.
  Verified live against the user's real installed models. Surfaced a
  real, separate, unresolved gotcha: the user's *default* connection
  (everyone but the Monk) was still pinned to a thinking model from a
  choice made before `llama3.2` was installed, silently overriding the
  auto-pick that would otherwise favor it — flagged directly, fix is a
  manual Connections-panel change, not yet confirmed done.
- `AGENT-EMBODIMENT-PLAN.md` written: giving AI residents actual bodies
  (act, not just answer), scoped to a bounded first version (one
  resident, one real action) instead of a full action API on day one.
- `LIBRARY-GROWTH-PLAN.md` expanded with a dedicated research-papers
  plan: more real sources (PLOS, OpenAlex, Unpaywall, bioRxiv/medRxiv,
  SciELO), and the actual identified gap — arXiv already fetches a
  PDF, but nothing turns it into plain text, so it never becomes a real
  shelf entry. `tools/caravan/pdf-to-text.py` named as the single
  missing piece, now the roadmap's #1 item.
- README's "What's next" reordered around the user's own stated north
  star instead of rough technical priority, and two "go big" Hopes and
  Dreams sections written at the user's explicit request: the best
  home office anyone's had, and what would make "AI worth everyone
  actually having" true rather than just truthfully claimed.
