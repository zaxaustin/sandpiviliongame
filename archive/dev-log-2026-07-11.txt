BUTLER-SEBASTIAN-PLAN.md steps 1-2 (his charter + chat presence) shipped
2026-07-10. Built the back half this session:

- DATA MODEL (step 3). calendar:[] added to freshData() in entities.js,
  with the same migration patch the other newer fields use (older saves
  read as empty — no migration needed). An event is { id, date, start,
  end, title, note }. Local, in the same save, exported/imported with
  everything else.

- ONE SOURCE OF TRUTH (step 5). upcomingItems() now folds in calendar
  events, so the HUD due badge, the Upcoming panel, and Sebastian's read
  all draw from one place. The honest part, following the archived-course
  precedent: only TODAY-OR-LATER events surface, so a past event never
  falsely nags as "overdue" the way a missed course deadline honestly
  should. Same-day items sort by start time. Verified the badge math: an
  event bumps the glanceable count but (being never < today) can never add
  to the "overdue" count — exactly right.
  Updated every upcomingItems consumer for the new 'event' kind: a shared
  upcomingIcon() helper (📚 course / 📅 event / 📝 grant), the Writing
  Desk's due line, and the Upcoming panel (clicking an event now opens the
  calendar on that day).

- CALENDAR UI + HIS DESK (step 4). A new #calendarOv overlay, openCalendar()
  in overlays.js: a month grid (prev/next month, today highlighted, a dot
  count per day) → click a day → a day/agenda view listing that day's
  events with a remove button and an add-event form (title, optional
  start/end time, optional note). A small .calgrid/.calcell CSS block added
  to style.css (plus themed date/time inputs). A 'calendar' station stands
  at Sebastian's desk (10,7) in buildWorkshop, with its own drawStation
  case in render.js (a red-banded desk pad on a stand) and an onAction
  dispatch in main.js — the exact Records Hall pattern. Two doors, one
  spot: the NPC for the conversation, the desk for the grid, plus a
  "📅 Open the calendar" button inside his chat.

- ADVISORY READ (step 6). butlerDayRead() (his AI grounding) now speaks to
  today's timed events directly. A new butlerAdvisoryLine() computes the
  overbooked / empty / neglected / well-kept state as one plain-text line
  in his own butler voice, shown at the top of the calendar — and computed
  with NO AI connected at all, so the advisory works for everyone and just
  gets richer when a model is present. A priority ladder (overdue >
  neglected sparks > overbooked > empty > well-kept), the most worth-saying
  thing said once. Computed only on opening the calendar — never a timer.

Every onclick handler registered in the Object.assign(window,{...}) export
block (the documented silent-fail gotcha). 'calendar' added to the smoke
test's KNOWN_STATION_KINDS list.
